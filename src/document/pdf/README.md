# PDF extraction (`src/document/pdf`)

Turns PDF.js text content into `Block` DTOs (`src/ipc/generated/Block.ts`) with
PDF-user-space locations, quality reasons and translation policies (spec §3.2–3.4, §4).

| File | Role |
| --- | --- |
| `pdfjs.ts` | Hardened `getDocument` loader, password hook, link annotations as data |
| `pdfjsAssets.ts` | Bundled worker / CMaps / standard fonts / decoder wasm via Vite `?url&no-inline` |
| `pageInput.ts` | `PDFPageProxy` → structured-clone-friendly `PdfPageInput` (text, styles, image ops) |
| `layout.ts` | Pure geometry: fragments → lines → tables → columns/zones → paragraphs |
| `extract.ts` | Classification, quality, policy, raw/source text + mapping, deterministic ids |
| `running.ts` | Cross-page running header/footer pass |
| `text.ts` | Rust-compatible source normalisation with offset mapping, hyphenation, UTF-16 safety |
| `coords.ts` | PDF ⇄ CSS conversions through `PageViewport`, hit test, visibility |
| `extract.worker.ts` / `extractWorkerCore.ts` / `extractClient.ts` | Off-main-thread extraction protocol |
| `testing/` | Test-only helpers (fixture loader for Node, synthetic items) |

Fixtures are generated by `node scripts/fixtures/make-pdf-fixtures.mjs` into
`tests/fixtures/pdf/` (deterministic; hand-written PDFs with standard Type1 fonts,
a Type3 font without Unicode, an image XObject; plus `*.expected.json` goldens).

## Algorithm (§4.1)

1. **Fragments.** Each `TextItem` is placed with its `transform` `[a b c d e f]`:
   baseline angle `atan2(b, a)` (snapped to quarter turns within 3°), font size
   `hypot(c, d)`, advance `width`, ascent/descent from the PDF.js style (default
   0.8/−0.2). Items are grouped by orientation; each group is analysed in its own
   *frame* (user space rotated so the baseline is +x and glyph-up is +y). Rects are
   rotated back exactly — no `height − y` anywhere. Whitespace-only items (PDF.js
   gap markers) never contribute geometry. Items completely outside the view box
   (crop box) are dropped and counted.
2. **Lines.** Fragments sharing a baseline (vertical overlap ≥ 50 % and baseline
   delta ≤ 0.6 em) form rows; super/subscripts join the row of the larger text.
   Rows are split into line segments at gaps > 0.9 em. List markers are re-joined
   with their text, equation numbers `(n)` with their formula; exact duplicate runs
   (faux bold) are dropped and reported as `overlapping_text`.
3. **Tables.** ≥ 2 consecutive rows with ≥ 3 short cells (≤ 30 chars, ≤ 4 words,
   ≤ 30 % of the content width) whose spans overlap become one atomic table unit,
   unless the cells look like narrow prose columns (uniform widths, ≥ 3 words).
4. **Columns / zones.** A gutter is a vertical white-space river: an x-interval
   covered by at most 25 % of the units, ≥ 0.9 em wide, with ≥ 2 side-by-side
   units on each side. Units crossing it are *spanning* (title, abstract, wide
   caption) if they overlap both columns (≥ 25 % each) or are centred on the
   gutter; spanning units cut the page into zones read top → bottom, and inside a
   zone the left column is read before the right (recursive → 3+ columns). A unit
   that crosses the gutter without clearly spanning is *intruding*: it is assigned
   to its majority side and its flow is marked unresolved. A gutter supported by
   < 3 side-by-side pairs, or with short fragments on both sides (form/table-like),
   is also unresolved.
5. **Paragraphs** (within one flow only — columns never mix): break on font size
   change > 12 %, bold/mono change, vertical gap > 1.35 × the flow's line pitch
   (lower quartile), a list marker, a short line ending a sentence, or an
   indentation change (first-line indent and hanging indents are recognised; code
   keeps its own indentation).
6. **Classification.** table → `missing_unicode ≥ 30 %` → `unknown` → monospace →
   `code` → math density / Symbol-font share / italic single letters → `formula` →
   `Figure|Fig.|Table|Listing|그림|표 n:` → `caption` → larger (≥ 1.15 × body) or
   bold-on-regular short block → `heading` → small text in the bottom 30 % starting
   with a marker → paragraph + role `footnote` → list marker → `list_item` → weak
   caption pattern → `caption` → `paragraph`. A bare page number in the top/bottom
   band gets role `page_number`.
7. **Text.** `rawText` = lines joined by `\n` (table cells by `\t`; code gets its
   indentation reconstructed from x offsets). Line-end hyphens are removed only for
   lowercase–lowercase continuations that are not a common compound prefix
   (`self-`, `non-`, …) and not attested hyphenated elsewhere on the page; capital /
   digit continuations keep the hyphen and only drop the break. Edits are applied
   before the Rust-compatible normalisation (`normalize_source_text`: NFC, Rust
   `char::is_whitespace` runs → one space, trim; code/formula untouched) and every
   change is recorded in `mapping.offsets` (merged identity spans).
   `mapping.textNodes` = `{ path: "item:<i>", rawStartU16, rawLenU16, nodeOffsetU16: 0 }`
   per contributing item; `location.itemRanges` are whole items in reading order.
8. **Ids** (must match Rust `domain::derive_block_id` / `derive_section_id`):
   `sha256(canonicalJson({extractionId, locator: "page:<i>", rawRange:
   "<firstItem>:<start>-<lastItem>:<end>", kind, occurrence}))`; section id
   `sha256(canonicalJson({extractionId, ordinal: pageIndex, locator}))`;
   `sourceHash = sha256(sourceText)`. Roles/policies are not part of the id, so the
   cross-page pass never changes ids.
9. **Cross page.** `detectRunningElements` flags blocks that repeat (NFKC, lower
   case, digit runs / roman numerals → `#`) in the top/bottom 12 % band on ≥ 3
   pages: role `running_header` / `running_footer`, policy `preserve`; nothing is
   removed. The last unfinished body paragraph of a page gets the candidate role
   `continues_on_next_page`; pages are never merged.

## Quality reasons and policy (§4.2)

| Reason | When | Effect |
| --- | --- | --- |
| `unresolved_columns` | ambiguous gutter / intruding line | block `low` → `manual_only` |
| `missing_unicode` | U+FFFD, C0/C1 controls, BMP PUA, empty string with width | `medium`; `low` if ≥ 10 % of the block or ≥ 30 % of the page (then kind `unknown`) |
| `overlapping_text` | duplicate or overlapping glyph runs on a line | `medium` |
| `likely_scan` | images but no usable text → **no blocks at all**; or a ≥ 85 % image page with a text layer (OCR) → blocks `medium` | page diagnostic |
| `rotated_text` | orientation differs from the page's dominant one, a non-quarter angle, or vertical writing | `medium`, `manual_only`, ordered after the dominant text |
| `low_text_density` | images present and < 0.0004 chars/pt² | `medium` |

Policy: `code`, `formula`, `table`, `figure`, running header/footer and page
numbers → `preserve`; `low` → `manual_only`; otherwise `auto` (high and medium).
`quality.reasons` are sorted; no numeric confidence is emitted (§4.1).

## Worker protocol

```
→ { type: 'extract', requestId, extractionId, pages: PdfPageInput[], detectRunning?: boolean }
← { type: 'result',  requestId, pageIndex, blocks: Block[], diagnostics }   one per page, in order
← { type: 'error',   requestId, pageIndex | null, message }                 a failed page does not stop the batch
← { type: 'running', requestId, updates: RunningElementUpdate[] }          after all pages (batch-local)
← { type: 'done',    requestId, cancelled }
→ { type: 'cancel',  requestId }                                            honoured between pages
```

`PdfExtractClient` wraps it. Running detection inside the worker only sees the
pages of one request; for documents extracted in several batches call
`detectRunningElements(allPages)` + `applyRunningUpdates` on the accumulated results.

## Integration notes

- `pdfjs.ts` imports `pdfjs-dist` lazily; `pdfjsAssets.ts` pulls every CMap, the
  14 standard font files and `openjpeg`/`jbig2` wasm in as hashed assets (≈ 2.7 MB,
  `?url&no-inline` so nothing becomes a `data:` URL). PDF.js gets sentinel base
  URLs and a `BinaryDataFactory` that fetches only those bundled files
  (`useWorkerFetch: false`). Not bundled: `quickjs-eval` (scripting), the
  `*_nowasm_fallback.js` decoders and the CMYK ICC profile.
- Open documents with `fontExtraProperties: true` (the loader default) so
  `pageInput.ts` can read real font names (bold / monospace detection).
- `isEvalSupported` no longer exists in pdfjs-dist 6.x (eval-based glyph
  compilation was removed); it is still passed as `false`. `convertToViewportRectangle`
  was also removed; `coords.ts` re-implements it from `convertToViewportPoint`.
- A non-http(s) `url` (e.g. `thoth-doc://…`) makes PDF.js use its XHR range
  transport; the protocol handler must answer `Range` requests with 206 and
  `Accept-Ranges`/`Content-Length`/`Content-Range` headers.
- CSP: `worker-src 'self'` (both workers are same-origin module scripts; no
  `blob:` needed in production), `connect-src 'self' thoth-doc:` (asset fetches +
  document ranges), `img-src 'self' blob: data:` for rendering, and
  `'wasm-unsafe-eval'` in `script-src` if JPX/JBIG2 images must be decoded with wasm.

## Known limits

- Struct trees (tagged PDF) are read only as a `tagged` diagnostic; marked-content
  ids are not mapped to items, so tags do not drive reading order yet.
- Items are atomic: a single PDF.js item that spans a gutter or a paragraph
  boundary cannot be split (item ranges always cover whole items).
- RTL scripts and vertical (`ttb`) CJK are only flagged (`rotated_text`); there is
  no bidi-aware line ordering or vertical column flow.
- No figure blocks are emitted (images are only used for scan / density /
  coverage diagnostics); caption ↔ figure proximity is not used, so a caption needs
  `Figure n:`-style punctuation or the weak pattern.
- Tables need ≥ 3 aligned short cells per row; 2-column tables are left as text and
  usually end up `unresolved_columns` (manual_only) rather than misordered prose.
- Hyphenation uses heuristics + page vocabulary, not a dictionary.
- Cross-page continuation is a candidate role only (§3.1), decided by punctuation.
- Thresholds were tuned on synthetic fixtures; they need calibration on the real
  §10.2 corpus (M0) before quality numbers are reported.
